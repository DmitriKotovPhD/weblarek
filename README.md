# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model--Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и . Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
 - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В слое данных, в проекте используются сущности: Товар, Покупатель, и ряд прочих, упомянутых ниже.  
<br/>

#### Интерфейс товара: IProduct.
Описывает единичный товар. Включает в себя описание всех полей товара, необходимых для идентификации товара, и предоставления данных товара, например: название, изображение, цена.

Поля интерфейса:  
`id: string` уникальный идентификатор товара.  
`description: string` подробное описание товара. Отображается в карточке товара.  
`image: string` uri картинки товара. Используется для отображения картинки товара в карточке товара и в каталоге. 
`title: string` наименование товара. Используется в карточке товара.  
`category: string` наименование категории товара.  
`price: number | null` цена товара. Может отсутствовать.  
<br/>

#### Интерфейс покупателя: IBuyer.
Описывает сущность покупателя. Включает в себя описание всех полей, необходимых для оформления заказа, например: способ оплаты, адрес, телефон, email.  
Используется при оформлении заказа.  

Поля интерфейса:  
`payment: TPayment` способ оплаты. Это перечисляемый тип. Может принимать одно из заранее предопределённых значений. Тип `TPayment` может принимать одно из следующих значений: `'card' | 'cash' | ''`.  
`email: string`  email-адрес покупателя. Используется при оформлении заказа.  
`phone: string` номер телефона покупателя.  
`address: string` физический адрес покупателя. Может быть использован для доставки заказа.  
<br/>

#### Интерфейс IProductListResponse
Формат описания ответа сервера на запрос получения набора товаров.

Поля интерфейса:  
`total: number` общее количество товаров в выборке  
`items: IProduct[]` массив товаров  
<br/>  

#### Интерфейс IOrder
Формат описания запроса на создание заказа для отправки на сервер.  

Расширяет интерфейс `IBuyer`. Добавляет поля, специфичные для описания заказа: `total`, `items`;

Уникальные поля интерфейса:  
`total: number` сумма заказа  
`items: string[]` список id товаров в заказе  
<br/>

#### Интерфейс IOrderResponse
Формат описания ответа сервера на запрос создания заказа.

Поля интерфейса:  
`id: string` идентификатор заказа  
`total: number` сумма заказа  
`name: string` текстовый заголовок ответа  
`error: string` текст сообщения об ошибке. Может отсутствовать.  
<br/>

#### Класс Cart
Корзина с товарами для оформления заказа. Это временное хранилище списка товаров, выбранных пользователем для дальнейшей покупки. 
Товары можно добавлять в корзину, удалять из корзины. Есть функционал динамического подсчёта количества товаров и подытога стоимости.  

Конструктор класса не принимает параметров.  

Поля класса:  
`itemsList: IProduct[]` массив товаров (в корзине), выбранных покупателем для покупки.


Методы класса:  
`getItems(): IProduct[]` получить все товары из корзины  
`addItem(product: IProduct): void` добавить указанный товар в корзину (в массив товаров корзины)  
`removeItem(productId: string): void` удалить товар из корзины  
`removeAll(): void` удалить все товары из корзины (очистка корзины)  
`getSubtotal(): number` получить текущий подытог номинальной суммарной стоимости товаров в корзине  
`getItemsCount(): number` получить количество товаров в корзине  
`has(productId: string): boolean` проверить наличие товара  
<br/>
<br/>

#### Класс Buyer 
Описывает сущность покупателя. Хранит данные покапателя, необходимые для оформления заказа: выбранный способ оплаты, email, телефон, адрес (для чеков и доставки).
Предоставляет функционал валидации данных.

Конструктор класса не принимает параметров.  

Поля класса:  
`payment: TPayment  ` сохранённый метод оплаты  
`address: string`  адрес (для чеков и доставки)  
`phone: string` номер контактного телефона  
`email: string`  email-адрес покупателя  


Методы класса:  
`setData(buyer: Partial<IBuyer>): void` сохранить указанные данные покупателя. Предоставляет возможность сохранить как всю модель, так и частичный набор полей модели.  
`getData(): IBuyer` получить все данные покупателя  
`clearAll(): void` удаляет все данные покупателя  
`validate(): BuyerValidationErrors {}` валидировать данные покупателя

Базовый абстрактный класс формы. Наследует от Component.
Отвечает за базовый функционал работы с формой, например: 
- представление полей формы
- обработка событий
- отправка
- контроль валидности
- отображение ошибок

Конструктор класса:
`constructor(container: HTMLElement, protected eventBroker: IEvents)` в конструктор передаётся корневой элемент компонента (формы) в DOM,
и ссылка на инстанс брокера событий.

Поля класса:
`protected fields: HTMLInputElement[]`
`protected actionButton: HTMLButtonElement`
`protected errors: HTMLElement`

Методы класса:
`validate(): Errors[]`
`enableActionButton(enable: boolean): void`

### Слой Презентера
Данный слой содержит всю основную бизнес-логику веб-приложения.

#### События
- `catalog:data-changed` при изменении списка товаров (получении данных от сервера), необходимо обновить представление каталога
- `catalog:select` событие изменения выбранного товара
- `catalog:item-click` по нажатию на карточку товара в каталоге, показать представление (модальное окно) товара с полным описанием товара
- `cart:data-changed` срабатывает при изменении состава данных корзины: добавить товар в корзину, удалить товар из корзины
- `cart:delete` событие удаления товара из корзины
- `cart:show` показать корзину. Вызывается из Header, по нажатию на кнопку корзины, 
- `formData:input` событие ввода в поля формы
- `buyer:data-changed` событие ввода данных пользователя (собсоб платежа, адрес, телефон, email)
- `order:checkout` показать диалог оформления заказа. Вызывается из корзины по нажатию кнопки отправки корзины.
- `order:contacts` событие отправки формы с данными заказа
- `order:submit` событие отправки формы с контактами
- `order:success` показать пользователю окно об успешном размещении заказа.
- `modal:open` модальное окно было открыто
- `modal:close` модальное окно было закрто
